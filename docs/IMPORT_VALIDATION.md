# 通用导入机制（0.5.1）

## 符号单元

读取来源 JSON 的 PART、PIN、ATTR 和图形归属。转换库中的引脚编号和坐标必须与来源对应，矩形坐标也必须对应，然后写入各图元 OwnerPartId，PartCount 包括 AD 的公共单元 0。多单元中的引脚和图形不会再全部写入单元 1。无法匹配的来源拒绝自动归属。

预览默认显示单元 1，使用“切换单元”查看其他单元。AD 中多单元器件需要放置各单元，例如 U1A 和 U1B，它们属于同一个物理器件。原有错误符号重新导入后可以修复库；已经放置在原理图上的实例需要更新库并补放电源等单元。

## 封装与模型

校验引脚/焊盘完整映射、嵌入模型数量、模型 ID 唯一性、3D Body 引用和 STEP 完整性。复用封装必须同时满足图元一致和模型内容、变换一致。修复共享对象会隔离封装或模型，不改变其他元件。

来源模型的标题、URI、原始及归一化 STEP SHA256 保存在 binding-report.json。它们证明文件来源与绑定一致，不能证明来源模型的厂商标记、尺寸或电气规格符合数据手册。通用封装模型可能带其他型号的表面标记。

“替换 STEP”允许为本次导入选定本地模型。替换文件保存在缓存 overrides 目录，沿用来源的目标尺寸、旋转和偏移，并显示新预览。检查方向及引脚位置后再导入。替换一个器件不会覆盖其他器件的共享模型。后续重新搜索会读取上游模型；已导入的替换模型仍保存在主库内。

## 当前边界

没有 STEP 的器件保持明确提示并阻止当前完整导入流程，不会用别的器件补模型。无法支持的多单元图形拒绝自动转换。单元归属恢复当前覆盖后端输出的引脚、矩形、折线与椭圆；不等同于完整实现所有来源格式。

自动检查无法证明所有器件不会错乱。器件尺寸、引脚电气类型、隐藏引脚、厂商模型标记和 AD 各版本兼容性仍需实际核验。原生编译、实际放置及 PCB 更新属于独立验收阶段。
